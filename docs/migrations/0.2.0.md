# Migration notes for 0.2.0

## Unreleased

### CLI help and diagnostics

The generated help text no longer includes descriptive prose for the top-level
command, subcommands, or positional arguments. The usage line, command names,
options, and argument order remain available. Command syntax and normal roadmap
output are unchanged.

Scripts that inspect help output should rely on the usage line and command or
option names, not generated descriptions or a complete help-text snapshot. No
changes are needed for scripts that invoke commands using their existing
arguments.

Roadmap command failures still print a diagnostic to standard error and exit
unsuccessfully. With tracing enabled, their structured error event now records
a stable error class and static message instead of including the full error
text; the user-facing diagnostic remains on standard error. Automation should
read that diagnostic rather than parse the tracing event. Help remains on
standard output and exits successfully.

### Library errors and export API

`SourceLocation` is a new public type carrying a one-based `line` and `column`.
It is re-exported from the crate root.

`MapspliceError::InvalidRoadmap` and `MapspliceError::DanglingDependency` gain a
`location: Option<SourceLocation>` field. Their `Display` output starts with
`line N, column M:` followed by a space when the parser knows the source
position. Code that constructs either variant, or matches it exhaustively, must
supply or account for the new field.

Export failures are reported through a new `ExportError` enum, re-exported from
the crate root and reachable as `MapspliceError::Export`. Its `Drift` variant
reports a committed JSON export that differs from the Markdown source,
`InvalidCommitted` reports an unreadable or schema-invalid committed export, and
`Serialization` reports a serialization failure. `MapspliceError::class()`
delegates to them, giving `export_drift`, `invalid_export`, and
`json_serialization`. Filesystem failures remain `MapspliceError::Io`, since
they belong to the caller-supplied reader rather than the export contract.

`MetricsSnapshot` gains five export counters: `export_attempts`,
`export_emitted`, `export_matches`, `export_drifts`, and `export_failures`.
Code that constructs the snapshot directly, or matches it exhaustively, must
supply or account for them. The counters are process-local and reset when the
process restarts.

`CommandKind` gains an `Export { format, check }` variant, and `ExportFormat`
(currently `Json`) is public and re-exported from the crate root. The `export`
command is read-only: it writes JSON to standard output, or validates a
committed export with `--check`, and never rewrites the target.

### Roadmap JSON export and drift validation

`mapsplice export` emits a deterministic, versioned JSON representation of a
roadmap. To adopt it, commit an export beside the Markdown source and validate
it in continuous integration:

```sh
mapsplice export --format json docs/roadmap.md > docs/roadmap.json
mapsplice export --check docs/roadmap.json docs/roadmap.md
```

The check exits successfully without output when the committed file matches the
fresh export. It exits unsuccessfully and prints one line per semantic
difference, naming the item and field that changed, when the Markdown source
has moved ahead of the committed export. Regenerate the export after reviewing
the reported drift.

JSON consumers should treat `format_version` as part of the contract: the
current value is `1`, and a future incompatible change increments it. The
[roadmap export format](../roadmap-export-format.md) documents the fields,
their ordering guarantees, and the drift vocabulary. The
[users' guide](../users-guide.md#export) covers the command-line workflow.

### Numbered checkbox details cannot nest beneath a checkbox detail

The parser now rejects a numbered checklist item nested beneath a checkbox
detail, for example:

```markdown
- [ ] 1.1.1. Task.

  - [ ] Detail.

    - [ ] 1.1.1.1. Nested sub-task.
```

Previously this document parsed, and only the export adapter rejected it. Edit
commands could therefore accept a roadmap that `mapsplice export` could not
represent. Only a task owns addendum sub-tasks, so move the numbered item into
the task's own list. The same document now fails at parse time with a source
location instead of failing later during export.

### Dependency clauses split across lines

Dependency scanning now recognizes a `Requires` clause whose anchor is
separated from the keyword by a line break, including a soft wrap that Markdown
merges into one text node. Such an anchor is renumbered with the rest of the
document. Previously the newline made the scanner skip the anchor, so an insert
or delete that shifted the referenced task could leave a stale anchor in a
hard-wrapped clause. A clause terminator such as `;` or a sentence-ending `.`
still stops the scan, so unrelated text after a completed clause is unaffected.

Documents that hard-wrap `Requires` lines may therefore show dependency
rewrites on the first run after upgrading. Review the rewritten anchors and
commit them; the rendered Markdown is otherwise unchanged.
